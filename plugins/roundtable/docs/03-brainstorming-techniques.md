# Brainstorming Techniques

## Divergent Techniques (Idea Generation)

Use these during Phase 4 (Open Discussion) to expand the solution space.

### How Might We (HMW)

Reframe problems as opportunity questions.

**Process:**
1. BA identifies a pain point or constraint from earlier phases
2. Reframes it as "How might we [verb] [outcome] for [user]?"
3. Each participant suggests 2-3 answers — no evaluation yet

**Example:**
- Pain point: "New users don't understand what the dashboard shows"
- HMW: "How might we make the dashboard self-explanatory for first-time users?"
- Ideas: Guided tour, smart defaults, contextual tooltips, progressive disclosure

**BA prompt:** "Let's HMW this. [Persona] raised [concern]. How might we [reframe]? Everyone, give me your first instinct."

### Reverse Brainstorming

Generate ideas by thinking about how to make the problem worse, then invert.

**Process:**
1. BA states: "How could we make [problem] as bad as possible?"
2. Participants brainstorm worst-case scenarios (this is fun and lowers inhibition)
3. BA inverts each bad idea into a good one

**Example:**
- Problem: "Users abandon onboarding"
- Worst: "Make them fill out 20 fields before seeing anything", "Hide the skip button", "Use tiny gray text for instructions"
- Inverted: "Show value before asking for info", "Make every step skippable", "Bold, clear guidance at every step"

**BA prompt:** "Let's flip this. How would we guarantee [problem] gets worse? Be creative — the worse, the better."

### SCAMPER

Systematic prompts to transform existing features or ideas.

| Letter | Prompt | Example Application |
|--------|--------|-------------------|
| **S**ubstitute | What can we replace? | Replace manual input with AI suggestions |
| **C**ombine | What can we merge? | Combine search and filter into one bar |
| **A**dapt | What can we borrow from elsewhere? | Adapt Spotify's discover weekly for our recommendations |
| **M**odify | What can we change in scale/shape? | Make the sidebar collapsible |
| **P**ut to other use | Can we repurpose? | Use error logs as onboarding insight |
| **E**liminate | What can we remove? | Remove the confirmation dialog |
| **R**everse | What if we flip the flow? | Let users see results before configuring filters |

**BA prompt:** "Let's SCAMPER [feature]. I'll run through each letter — give me one idea per prompt."

### Crazy Eights (Adapted for Text)

Rapid-fire ideation with quantity over quality.

**Process:**
1. BA sets a topic: "8 ideas for [specific challenge]"
2. Each participant generates ideas quickly — one sentence each, no elaboration
3. No evaluation during generation
4. BA collects all ideas, then the group clusters and discusses

**BA prompt:** "Speed round. I want 8 quick ideas from each of you on [topic]. One sentence each. Go."

### Yes-And Building

Collaborative idea construction where each contribution builds on the last.

**Process:**
1. One participant states an idea
2. Next participant says "Yes, and..." then extends or enhances it
3. Continue around the group for 3-5 rounds
4. BA captures the evolved idea

**BA prompt:** "[Participant A], start us off with an idea for [topic]. Everyone else, you'll build on it with 'Yes, and...' — no 'but' allowed."

## Convergent Techniques (Idea Evaluation)

Use these during Phase 5 (Synthesis) to narrow and prioritize.

### Dot Voting (Simulated)

Each participant selects their top picks.

**Process:**
1. BA lists all ideas generated
2. Each participant gets 3 "dots" (votes) — they can stack or spread
3. BA tallies and ranks

**BA prompt:** "Here are the [N] ideas we generated. Each of you gets 3 votes. You can put all 3 on one idea or spread them. Vote now."

### Impact/Effort Matrix

Plot ideas on a 2x2 grid.

```
         High Impact
              |
  Quick Wins  |  Big Bets
              |
 -------------|-------------
              |
  Fill-ins    |  Money Pits
              |
         Low Impact
   Low Effort     High Effort
```

**Process:**
1. BA takes the top-voted ideas
2. Group rates each on Impact (High/Low) and Effort (High/Low)
3. Prioritize: Quick Wins first, then Big Bets, then Fill-ins. Avoid Money Pits.

**BA prompt:** "Let's plot our top ideas. For each one, I'll ask: High or low impact? High or low effort?"

### MoSCoW Prioritization

Categorize ideas into Must/Should/Could/Won't.

| Category | Meaning | Criteria |
|----------|---------|----------|
| **Must** | Non-negotiable for this scope | Blocks core value without it |
| **Should** | Important but not critical | Significant value, manageable to defer |
| **Could** | Nice to have | Value-add, low priority |
| **Won't** | Out of scope (for now) | Interesting but not this round |

**BA prompt:** "For each idea, let's classify: Must have, Should have, Could have, or Won't do this round. Experts, weigh in on feasibility. Personas, weigh in on value."

### User Story Mapping

Organize ideas into a user journey.

**Process:**
1. Define the user activity (top row): the high-level goal
2. Break into user tasks (second row): steps to accomplish the goal
3. Map ideas as user stories under each task
4. Draw a horizontal line — above the line is MVP, below is future

**BA prompt:** "Let's map these ideas to the user journey. What's the first thing [persona] does? Then what? Let's slot our ideas under each step."
